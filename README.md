# Aevum AI 0.2.4 — Pretrained Neural Vocabulary

Aevum AI 0.2.4 keeps the polished Aevum 0.1.x desktop shell and replaces the legacy RMEM/two-worker memory path with the compact MicroBrain neural-memory runtime developed through MicroBrain 0.9.55–0.9.57.


## 0.2.4 pretrained neural vocabulary

Aevum now ships a **lazy read-only bank of 10,252 active neural token labels backed by 10,241 distinct exact MBE2 prototypes**. The bank contains **10,000 frequency-ranked English words**, **224 additional modern Aevum conversational/technical words**, and **28 punctuation/digit tokens**. Its AVNP neural pack is about **196.8 MB uncompressed** and is not copied into each user's writable memory; the manifest is loaded at startup while prototype blobs stay on disk until actually used.

The 10,000-word frequency base represents about **96% of token occurrences** in the local 29k-word spelling-frequency corpus used for ranking, versus about 91% for the earlier 5,000-word target. The supplement preserves practical first-run terms such as `GRANITE`, `GGUF`, `GPU`, `API`, decoder/encoder vocabulary, contractions, chat language, and common household/car/technical words that frequency-ranked book English can miss.

This is acceleration, not a text-memory substitute. Every active label points to an exact neural event prototype generated by the same deterministic 128-neuron encoder. Known-token ingest therefore needs **zero neural simulation**. In the final-pack verification, `THE RED FISH LIKES COLD WATER STORY MANUAL` stored in roughly **0.0007 s** with zero new prototypes and decoded back exactly.

Five frequency candidates are deliberately **quarantined instead of forcing a segmentation change**: `ENGAGE`, `ENGAGED`, `ENGAGEMENT`, `ENGAGING`, and `ENCAPSULATED`. Each single-word trace contains the same 39 ms internal silence between activity at 88 ms and 128 ms. They are recorded in `pretrained_vocabulary/quarantine.json` and backfilled with the next valid frequency-ranked words, so the active base still contains 10,000 usable words. Their common trace structure can be investigated later without risking ordinary ingest.

Unknown words still pass through the real 128-neuron encoder once and then join the user's writable personal prototype bank. The shipped bank is only a first-run accelerator; learning remains active.

## 0.2.3 reliability/performance correction

This release fixes two issues exposed by real Granite use.

- **Granite native tools are no longer permission-gated by a home-grown chat-template substring heuristic.** Aevum always supplies its neural-memory/web function schemas to the local Executive. Granite 4.2's documented OpenAI-style tool protocol is preserved, including assistant tool calls followed by `role=tool` results.
- When automatic neural hints surface, Granite receives enough reasoning budget to decide whether those hints matter. The wording itself never forces a recall or tool call. Ordinary chat may still use the lower-latency mode.
- Recent visible chat remains fast working context, but is now bounded (default ~14k characters inside the configured recent-turn window) so an 8K GGUF context still has room for the system prompt, five tool schemas, full recalled documents, and the answer. The complete older turns remain in neural memory.
- New episodic stores use the validated 0.9.56 **lossless prototype/layout V3** representation. In the current deterministic/non-plastic encoder, a token is simulated once; later occurrences reuse the exact neural event prototype. Direct-vs-compiled neural event digests are regression-tested.
- Existing 0.2.0/0.2.1 V2 engrams remain compatible. Exact deterministic token regions already present in V2 memory can be promoted lazily into the V3 prototype cache instead of being simulated again.

A real migration test using the previously stored `RED FISH / COLD WATER` memories required **zero new neural simulations**: the first migrated V3 store took about 2.45 s including prototype persistence, while a repeated store took about 0.003 s. Completely unseen vocabulary still has to pass through the real 128-neuron encoder once.

## What changed

The visible application is still **Aevum AI**: same obsidian/neon-green branding, splash screen, left chat rail, multi-chat UX, assistant cards, Thinking/Tools presentation, Cognitive State, Activity, Settings, model start/stop controls, and GGUF browsing workflow.

The primary model architecture is now intentionally smaller:

- **Executive** — one local chat-capable GGUF, intended for Granite 4.2 Q6 on the user's machine. It owns conversation, reasoning, tool choice, web use, and neural recall.
- **Semantic Annotator (optional)** — one small Qwen3.5 ~2B GGUF. It runs after storage and attaches bounded meaning/state metadata such as tone, salience, correction, sentiment, topics, entities, urgency, hostility, praise, and affect deltas. It is never required to answer a turn and never replaces raw neural memory.

The legacy mandatory Observer + Memory-worker choreography is not part of the active runtime.

## Neural memory behavior

Every completed user and assistant message is encoded into compact continuous neural engrams with speaker, role, chat/message IDs and UTC timestamp as provenance. The original message body is not duplicated into the neural document metadata.

Context is deliberately layered:

1. **Recent chat** remains directly in the Executive context for immediate continuity.
2. **Automatic neural recall** silently searches current-message cues and supplies only metadata hints: document ID, timestamp, speaker/role, matching neural cues and bounded semantic tags. Historical body text is not auto-injected.
3. **Explicit recall** lets Granite search/open neural memory. When a result is needed, the runtime reconstructs and returns the **whole decoded document**, even if the document spans multiple compact engrams.
4. **Web evidence** is temporary private model evidence. Search/fetch receipts stored in chat/neural memory contain the purpose/query and a compact result list, not downloaded page bodies.
5. **Normal chat messages** are archived neurally in full after the answer is complete, preventing the current question from being mistaken for older memory.

The neural decoder retains the guarded multiscale timing representation:

`0.5 ms · 1.0 ms · 2.0 ms · 4.0 ms`

## Neural minimap

Aevum's existing top-right model-status area includes a compact RTS-style **128-neuron minimap**. It is an instrument, not a decorative animation.

The 128 lights follow the real 8×16 neural layout. Brightness is always derived from stored neural evidence:

- **large memories** use actual per-neuron firing frequency inside bounded temporal windows;
- **small memories** additionally blend in real recurrent-route participation for finer relative-strength detail;
- a short display-only decay provides glow persistence but never creates neural activity or alters memory/decoder state.

The HUD is deliberately bounded so visualization cannot scale with document size. Large engrams do **not** walk hundreds of thousands of recurrent transmissions merely to draw the minimap. Incoming animation events are coalesced to the newest activity, the canvas reuses its 128 glow/core nodes, colors are quantized/cached, and unchanged neurons are not repainted.

The default **Smooth** profile runs at about 15 FPS with at most 36 sampled neural windows. **Balanced** and **Detailed** modes are available in Settings. The profile can be changed without reloading the GGUF.

A synthetic 220,000-route renderer benchmark on the packaging host improved first-pass minimap preparation from roughly **0.23–0.25 s** in 0.2.0 to about **0.011 s** in 0.2.1; repeated recalls use the bounded HUD cache and are effectively immediate. This benchmark measures visualization preparation only, not neural encoding/decoding speed.

## Memory page

The Memory page remains part of the existing Aevum navigation. Merely opening it is intentionally metadata-only so a lifetime corpus does not get decoded into RAM. Search is explicit and reconstructs complete documents only when requested.

Deleting a visible chat deletes that transcript/session only. It does not erase already-lived neural memories.

## GGUF setup

Run `SETUP.bat` for the Vulkan-oriented Windows setup, then `RUN.bat`.

In **Settings**:

- choose the Granite Q6 (or another chat-capable GGUF) in **Executive**;
- optionally choose a Qwen3.5 ~2B GGUF in **Semantic Annotator** and enable it;
- click **Start model**.

The Executive loader remains model-agnostic at the application level and lets llama-cpp-python use the model's embedded chat template/tool capabilities when available.

Optional hosted OpenAI fallback can use the `OPENAI_API_KEY` environment variable. The key is not stored in Aevum's config.

## Web tools

The local Granite path retains normal runtime web search, web fetch and current-weather tools. Full fetched evidence is passed privately to the Executive while compact receipts are shown/stored. URL validation rejects local/private network targets.

## Persistence

- `data/chats.json` — visible session/chat history and UI continuity.
- `data/neural_memory/` — compact persistent neural memory and provenance.
- model files may live anywhere; Settings stores their paths.

At startup Aevum reconciles visible transcript message IDs against neural memory. A message that reached `chats.json` but was not neurally archived because of a crash is encoded on the next launch.

## Lineage

This is a new AevumAI branch, not a renamed MicroBrain lab build. MicroBrain supplied the neural encoder/decoder/memory subsystem; Aevum supplies the user-facing chat product. Historical 0.1.42 RMEM/two-worker source and docs are preserved under `history/` for audit/reference but are not imported by the active runtime.

See `ARCHITECTURE.md`, `BUILD_STATUS.md`, and `neural_docs/` for implementation and experiment history.


## Memory autonomy (0.2.3)

The current message is used to search the neural index for relevant metadata-only memory hints. Those hints are suggestions, not commands. Granite independently decides whether to open/search any hinted memory or ignore it. Words such as `remember`, `recall`, or `earlier` do not force a memory tool call.
